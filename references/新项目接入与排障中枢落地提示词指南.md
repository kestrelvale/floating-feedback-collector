## 1. 参数提取与架构规范说明

为了避免用户手动修改繁琐的命令行参数，本套指南通过在提示词头部**显式结构化提取关键环境参数**，并指示 AI Agent 自动读取当前项目环境进行自适应绑定：

- **线上模式提取参数**:
  - `ONLINE_DOMAIN`: 线上公网域名或服务器 IP（例如 `43.139.67.247` 或 `api.yourdomain.com`）
  - `ONLINE_PORT`: 线上生产/测试服务对外访问端口（例如 `23333` 或 `8888`）
  - `LOCAL_PORT`: 本地开发中台调试端口（默认 `8888`，若冲突自动自适应顺延至 `8889`~`8899`）
- **本地模式提取参数**:
  - `LOCAL_PORT`: 本地轻量开发服务端口（默认 `8888`，智能探测并避免冲突）

## 2. 提示词一：【线上模式 (Online)】全自动部署与升级提示词

> **使用场景**: 项目拥有公网/内网测试服务器，需要让远程测试人员、甲方、产品经理在公网提交反馈，数据统一集中存放在云端服务器，本地开发中台与线上中台实时镜像一致，Agent 本地排障结案后自动回推云端。

```markdown
请帮我在当前项目中完整接入/升级落地「悬浮问题反馈收集器与 Agent 闭环排障中枢套件 (V3.2.0 线上模式)」。请严格按照以下标准流程（SOP）全自动执行，无需我手动修改命令或拼接参数：

================================================================================
【📌 参数提取与配置区】:
- 线上服务器域名/IP [ONLINE_DOMAIN]: 43.139.67.247
- 线上服务访问端口   [ONLINE_PORT]:   23333
- 本地服务监听端口   [LOCAL_PORT]:    8888
- 官方 Git 代码仓库  [GIT_REPO]:      https://github.com/kestrelvale/floating-feedback-collector.git
================================================================================

### 🚀 执行要求与标准化步骤:

#### 第一步：动态拉取官方最新套件源码
1. 检查本地是否存在全局套件目录 `~/.codex/skills/floating-feedback-collector/`，如不存在则克隆，已存在则强制同步最新主干：
   ```bash
   SKILL_DIR="$HOME/.codex/skills/floating-feedback-collector"
   if [ -d "$SKILL_DIR/.git" ]; then
     echo "==> 正在更新已有套件至最新版本..."
     cd "$SKILL_DIR" && git fetch origin && git reset --hard origin/main
   else
     echo "==> 正在从官方仓库克隆最新套件..."
     mkdir -p "$HOME/.codex/skills"
     git clone "https://github.com/kestrelvale/floating-feedback-collector.git" "$SKILL_DIR"
   fi
   ```

#### 第二步：依据提取的参数执行线上模式初始化
1. 使用上述提取的 `ONLINE_DOMAIN` 与 `ONLINE_PORT` 拼接远程地址 `http://${ONLINE_DOMAIN}:${ONLINE_PORT}`，并结合 `LOCAL_PORT` 执行一键安装命令：
   ```bash
   node "$SKILL_DIR/cli/init.js" \
     --mode=online \
     --target=. \
     --port=8888 \
     --remote-url="http://43.139.67.247:23333" \
     --inject \
     --mcp \
     --yes
   ```
2. 检查并确认当前项目已落地核心资产：
   - 前端采集 SDK: `feedback-collector.js` 与 `html2canvas.min.js`
   - 五端排障中台: `feedback-dashboard.html` (确认远程地址指向 `http://43.139.67.247:23333`)
   - MCP 排障服务: `mcp/feedback-service.js` (确认已配置云端实时回推)
   - 本地服务与运维: `scripts/server.js`、`start.sh`、`stop.sh`、`status.sh`
   - 统一数据底座: `data/feedback_database.json` (四表结构，单真理源为云端)
   - 项目级 MCP 描述: `.mcp.json`

#### 第三步：智能扫描当前项目并自适应生成页面位置映射表 (URL ➔ Local File)
1. 自动扫描当前项目的所有核心 HTML 页面（如查找 `find . -maxdepth 3 -name "*.html"`）；
2. 自动在 `data/feedback_database.json` 的 `urlMappings` 字段中为这些页面建立映射规则（如 `MAP-001` 对应业务文件名），确保远程公网提单时能秒级命中本地源文件相对路径。

#### 第四步：启动服务并执行端到端自动化验证
1. 启动本地守护服务：
   ```bash
   bash scripts/stop.sh 2>/dev/null || true
   bash scripts/start.sh
   bash scripts/status.sh
   ```
2. 编写并运行轻量自动化测试脚本，必须 100% 验证以下 5 个门禁：
   - **门禁 ① 服务健康度**: 请求 `http://127.0.0.1:8888/api/feedback/summary` 与云端 `http://43.139.67.247:23333/api/feedback/summary` 确认均返回 200 OK；
   - **门禁 ② SDK 自动注入**: 抽查当前项目 HTML 文件，确认 `</body>` 前已包含 `<script src="feedback-collector.js"></script>`；
   - **门禁 ③ 中台可访问性**: 访问 `http://127.0.0.1:8888/feedback-dashboard.html` 返回 200 OK；
   - **门禁 ④ 纯按需同步**: 确认中台打开后无任何 `setInterval` 定时轮询，空闲期 0 网络负荷；
   - **门禁 ⑤ MCP 连通性**: 测试运行 `listFeedback()` 工具确认能正常读取云端工单数据。

#### 第五步：交付总结与验收卡
完成后输出标准的四状态机看板与【提请验收卡】（包含 Given-When-Then 人工体验指南与中台访问地址）。
```

## 4. 双模式关键参数对比与自适应解析表

| 参数标识符 | 参数名称 | 线上模式 (Online) 作用 | 本地模式 (Local) 作用 | Agent 自动解析逻辑 |
| :--- | :--- | :--- | :--- | :--- |
| `ONLINE_DOMAIN` | 线上域名 / IP | 远程云端 API 寻址与图片访问主机 | *(无需配置，自动置空)* | 优先读取提示词标注，未标注则读取项目现有线上配置或引导确认 |
| `ONLINE_PORT` | 线上对外端口 | 远程云端服务对外通信端口（如 23333） | *(无需配置，自动置空)* | 优先读取提示词标注，未标注默认探测或取标准端口 |
| `LOCAL_PORT` | 本地服务端口 | 本地中台展示与调试端口（默认 8888） | 本地独立 Node API 运行与中台端口 | 优先取 8888；通过 `lsof -ti :8888` 探测，若占用自动顺延 |
| `GIT_REPO` | 官方代码仓库 | 动态拉取最新 SDK 与中台模板源码 | 动态拉取最新 SDK 与中台模板源码 | 锁死官方权威源: `https://github.com/kestrelvale/floating-feedback-collector.git` |

## 5. 验收标准与质量门禁规范 (Definition of Done)

无论使用线上模式还是本地模式，Agent 执行完成后必须满足以下质量门禁方可宣告交付：

1. **零白屏与代码完整性**: 目标项目打开任意页面无 JS 运行时异常，控制台 0 报错；
2. **SDK 样式与手势正常**: 页面右下角成功渲染 42px 磨砂圆球，手势拖拽吸边与滚动避让流畅；
3. **真实快照捕获**: 点击反馈能正常抓取当前视口 DOM 快照并生成缩略图与全屏 Lightbox；
4. **单真理源数据隔离**: 线上模式只与云端通信，本地模式绝对零外部网络外发，两模式数据互不污染；
5. **按需动作驱动**: 中台无盲目定时轮询，空闲期 0 网络负荷，只在打开、提单、结案、手动刷新时产生请求；
6. **提供可点击体验地址**: 交付时必须在提请验收卡中给出清晰可点击的本地或线上中台 URL。
