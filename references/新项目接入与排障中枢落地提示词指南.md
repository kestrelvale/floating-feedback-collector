# 新项目接入与排障中枢落地提示词指南 (V3.2.0 零硬编码·项目自适应端口版)

> **核心设计原则**: 
> 1. **🚫 严禁任何硬编码默认端口与 IP**：绝不允许在提示词与命令中预设 `8888`、`23333` 等固定端口，彻底杜绝多项目在同一台服务器或本地开发机上部署时发生**端口争抢与服务冲突（防止把其他项目搞废）**！
> 2. **🧭 专属项目参数动态探测与提取机制**：指示 AI Agent 必须根据当前接入项目的实际环境（读取该项目的部署脚本、Nginx 虚拟主机配置、`package.json`、开发服务脚本）**动态提取或由用户为该项目分配的专属独立端口与域名**！
> 3. **🔗 全链路强引用复用**：所有安装命令、服务启动、验证测试与交付验收卡，必须 100% 动态引用探测/提取出的变量，一处探测，全局生效。

## 1. 多项目共存与端口防冲突机制说明

在企业级服务器或开发者本地物理机上，通常会同时运行**数十个独立的前端/原型系统**。如果套件存在固定默认端口，多个项目部署到同一服务器时，后部署的项目必定会覆盖、冲突或杀死先前的项目服务。

为此，本套件确立**“零预设、按项目动态定标”**原则：
- **线上模式 (Online)**:
  - 域名与端口必须对应**当前项目在线上被分配的专属虚拟主机或反代端口**（例如项目 A 用 `10001`，项目 B 用 `10002`）；
  - Agent 优先从当前项目的部署配置文件（如 `deploy.sh`、Nginx conf、`.env`）中自动探测提取，或由用户为该项目指定；
- **本地模式 (Local)**:
  - 本地端口必须为**当前项目专属的本地独立端口**；
  - Agent 自动检查当前项目已有的开发脚本（如 `start.sh`、`vite.config`、`package.json`）中规划的端口，或运行动态寻空脚本自动分配未被占用的端口。

### 🚀 执行要求与标准化步骤:

#### 第一步：智能探测与专属变量动态绑定 (严禁写死默认端口)
Agent 首先检查当前项目目录，自动探测或提取当前项目的专属参数，并导出环境变量：
```bash
# 1. 动态确定线上服务器配置 (优先使用声明区参数，或从当前项目部署配置中提取)
ONLINE_DOMAIN="${ONLINE_DOMAIN:-<填写当前项目线上域名或IP>}"
ONLINE_PORT="${ONLINE_PORT:-<填写当前项目线上专属端口>}"
REMOTE_URL="http://${ONLINE_DOMAIN}:${ONLINE_PORT}"

# 2. 动态探测本地空闲独立端口 (自动检查端口占用，绝不与其他项目冲突)
find_free_port() {
  local port=8000
  while lsof -ti :$port >/dev/null 2>&1 || nc -z 127.0.0.1 $port >/dev/null 2>&1; do
    port=$((port + 1))
  done
  echo "$port"
}

# 若未指定本地端口，自动分配一个未被占用的独立空闲端口
if [ -z "$LOCAL_PORT" ] || lsof -ti :"$LOCAL_PORT" >/dev/null 2>&1; then
  LOCAL_PORT=$(find_free_port)
fi

GIT_REPO="https://github.com/kestrelvale/floating-feedback-collector.git"
SKILL_DIR="$HOME/.codex/skills/floating-feedback-collector"

echo "==> 当前项目专属绑定参数 (已通过动态探测，零端口冲突风险):"
echo "  • 线上服务器地址 [REMOTE_URL]: ${REMOTE_URL}"
echo "  • 本地专属监听端口 [LOCAL_PORT]:  ${LOCAL_PORT}"
```

#### 第二步：从官方仓库动态拉取最新套件源码
```bash

  echo "==> 正在更新已有套件至最新版本..."

  echo "==> 正在从官方仓库克隆最新套件..."

#### 第三步：依据当前项目专属参数执行线上模式初始化
```bash

node "$SKILL_DIR/cli/init.js" \
  --mode=online \
  --target=. \
  --port="${LOCAL_PORT}" \
  --remote-url="${REMOTE_URL}" \
  --inject \
  --mcp \
  --yes
```

- 前端采集 SDK: `feedback-collector.js` 与 `html2canvas.min.js`
- 专属排障中台: `feedback-dashboard.html` (确认已绑定 `${REMOTE_URL}`)
- MCP 排障服务: `mcp/feedback-service.js` (确认已配置向 `${REMOTE_URL}` 实时回推)
- 本地服务运维: `scripts/server.js`、`start.sh`、`stop.sh`、`status.sh` (确认监听端口已配置为 `${LOCAL_PORT}`)

#### 第四步：自适应建立当前项目的页面位置映射表 (URL ➔ Local File)
1. 自动扫描当前项目目录下的核心 HTML 页面（`find . -maxdepth 3 -name "*.html"`）；
2. 自动在 `data/feedback_database.json` 的 `urlMappings` 中为这些页面建立映射规则（如 `MAP-001` 对应项目实际文件名），确保公网提单后直接命中当前项目的具体本地源文件相对路径。

#### 第五步：启动当前项目本地服务与五维自动化验证
1. 启动当前项目专属守护服务：
   ```bash
   bash scripts/stop.sh 2>/dev/null || true
   bash scripts/start.sh
   bash scripts/status.sh
   ```
2. 运行自动化测试验证，必须 100% 验证以下门禁：

   - **门禁 ② 线上服务连通性**: 请求 `curl -s ${REMOTE_URL}/api/feedback/summary` 确认返回 200 OK；
   - **门禁 ③ SDK 自动注入**: 抽查当前项目 HTML 页面，确认 `</body>` 前已包含 `<script src="feedback-collector.js"></script>`；

   - **门禁 ⑤ 纯按需同步**: 确认中台打开后无任何 `setInterval` 定时轮询，空闲期 0 网络负荷；

测试全部通过后，输出标准的四状态机看板与【提请验收卡】：

```

## 5. 质量验收门禁规范 (Definition of Done)

无论使用线上模式还是本地模式，Agent 执行完成后必须满足以下质量门禁方可宣告交付：

1. **端口零冲突**: 启动的服务端口确认为当前项目独立占用，未影响或覆盖机器上的其他已有服务；
2. **零白屏与代码完整性**: 目标项目打开任意页面无 JS 运行时异常，控制台 0 报错；
3. **SDK 样式与手势正常**: 页面右下角成功渲染 42px 磨砂圆球，手势拖拽吸边与滚动避让流畅；
4. **真实快照捕获**: 点击反馈能正常抓取当前视口 DOM 快照并生成缩略图与全屏 Lightbox；
5. **单真理源数据隔离**: 线上模式只与云端通信，本地模式绝对零外部网络外发，两模式数据互不污染；
6. **按需动作驱动**: 中台无盲目定时轮询，空闲期 0 网络负荷，只在打开、提单、结案、手动刷新时产生请求；
7. **参数全链路动态一致**: 交付卡中的中台体验地址必须与实际探测绑定的 `${LOCAL_PORT}` 或 `${REMOTE_URL}` 完全一致。
